# Postman коллекция

1. Импортируйте `lab3.postman_collection.json` в Postman.
2. В переменных коллекции укажите `adminUser` и `adminPassword` (пароль оставьте только локально, **не экспортируйте** его).
3. `baseUrl` по умолчанию `http://localhost:8080`.
4. Запустите папки **по порядку** через Collection Runner. Тесты сохраняют реальные ID в переменных коллекции.
5. Для воспроизводимости используйте чистую учебную БД либо создавайте новые данные. Email в запросах содержит `{{$guid}}`.

**Пять бизнес-операций**: публикация (№4), старт (№1), проверка ответов (№2), завершение (№3), отчёт (№5). Папка 03 показывает удаление решения только из незавершённой попытки. `ExamAttempt` изменяется через бизнес-операцию finish; `TaskSolution` намеренно неизменяем (нет PATCH), поскольку повторная проверка могла бы исказить результат. Это правила предметной области, не отсутствующие случайно endpoints.

Негативные HTTP-проверки ожидают HTTP 400. Доступ ко всем запросам: HTTP Basic администратора. Сохранённые ID также могут существовать после предыдущего запуска, поэтому запуск основной папки повторно создаёт новые сущности.
